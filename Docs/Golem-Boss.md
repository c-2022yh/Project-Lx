# 골렘 보스 사용법

## 바로 배치하기

- 프리팹: `Assets/Prefabs/Bosses/Boss_Golem.prefab`
- 기존 플레이어가 있는 씬에 프리팹을 드래그한다. 몸체 CapsuleCollider2D 아래쪽이 바닥에 닿도록 배치한다. 기본 크기에서 루트는 바닥보다 Y 1.8 위에 있다.
- 바닥은 **GameObject Layer = Ground**, 플레이어 몸체는 **Player**를 사용한다. Sorting Layer와는 별개다.
- 기본형은 **제자리에서 공격하는 보스**다. 평평한 바닥과 좌우 약 10유닛의 회피 공간을 기준으로 시작한다. 루트 Scale은 `(1, 1, 1)`을 유지한다.
- 플레이어가 18유닛 이내에 들어오면 전투를 시작한다. 첫 공격까지 1초 여유가 있다.
- 기존 씬, 플레이어 프리팹, 일반 적 프리팹은 수정하지 않았다. 보스방 문 잠금이나 스테이지 이동은 현재 프리팹에 포함하지 않는다.

프리팹을 새로 생성해야 할 때만 `Project Lx > Boss > Create Golem Prefab`을 사용한다. 이미 프리팹이 있으면 선택만 하며 이미지와 수치를 덮어쓰지 않는다.

## 구현된 전투 규칙

| 항목 | 기본 동작 |
| --- | --- |
| 보스 체력 | 300. 기존 Enemy/EnemyHealth로 플레이어 공격을 받음 |
| 몸체 접촉 | 피해 없음. 플레이어 몸체와의 물리 충돌도 제외해 통과 가능 |
| 넉백 | 보스에는 EnemyKnockback을 붙이지 않으며 X 이동을 고정 |
| 전조 | 팔을 드는 임시 동작과 빨간 사각형. 경고 중 피해 없음 |
| 타격 | 표시된 사각형과 동일한 월드 좌표/크기로 Physics2D.OverlapBox 검사 |
| 방향/위치 | 각 경고가 생성된 순간 확정. 이후 플레이어를 따라가지 않음 |
| 중복 판정 | 한 타격 영역은 같은 플레이어에게 최대 한 번 피해. 다중 콜라이더 중복 방지 |
| 회피/무적 | 기존 PlayerHealth / PlayerHitReaction의 무적 규칙 사용 |
| 체력바 | 머리 위에 임시 사각형 체력바 표시 |

빨간 영역은 이 2D 횡스크롤 게임에서 **실제로 피해를 받는 높이까지 포함한 단면**이다. 바닥의 얇은 장식만 표시하는 구조가 아니다. 따라서 내려찍기/강타는 점프로 벗어날 수 있고, 낙석은 높은 사각형을 옆으로 피하는 방식이다.

| 패턴 | 기본 전조 | 범위 (가로 × 세로, 월드 유닛) | 회복 | 재사용 대기 |
| --- | --- | --- | --- | --- |
| Front Slam | 1.1초 | 전방 4 × 1.4, 중심 X는 바라보는 방향으로 3.2 | 1.4초 | 3초 |
| Wide Ground Crush | 1.5초 | 보스 중심 9 × 1.3 | 1.8초 | 6초 |
| Sequential Rockfall | 각 지점 1.2초 | 각 2.2 × 5 | 마지막 타격 후 1.6초 | 5초 |

- 낙석은 기본 3회, 0.45초 간격으로 플레이어의 당시 위치를 바닥에 투영해 표시한다. 각 표시마다 온전한 전조 시간을 준다. 마지막 경고의 실제 타격까지 기다린 뒤 회복한다.
- 공격 준비 시간은 공격 동작의 Prepare 프레임 전체, 타격 시간은 Strike 프레임 전체, 회복 시간은 Recovery 프레임 전체에 대응한다. **Strike 배열의 첫 프레임을 바닥에 닿는 타격 자세로 준비한다.**
- 거리 조건과 패턴별 쿨타임을 확인하며, 다른 선택지가 있으면 직전 패턴의 연속 반복을 피한다.
- 체력 50% 이하에서는 현재 패턴/회복이 끝난 뒤 페이즈 전환 동작을 1.6초 재생한다. 이후 두 패턴을 연결하며 첫 회복은 0.45초, 마지막 회복은 원래 시간을 사용한다. 전조 시간은 줄이지 않는다. 연결 가능한 패턴이 쿨타임 중이면 기다린다.

## 쫄몹 소환

- 체력 **70%, 35%** 이하에서 각 한 번 예약한다. 공격 중 체력이 내려가도 진행 중인 공격을 갑자기 끊지 않는다.
- 양쪽 바닥의 **보라색 표시**를 1.8초 보여준 뒤 기존 `Enemy_Slime.prefab`을 최대 2마리 소환한다. 빨간 공격 경고와 구분되며 소환 표시 자체는 피해가 없다.
- 소환 뒤 2초 휴식하고 공격을 재개한다. 한 번에 살아 있는 소환몹은 최대 2마리다. 자리가 없으면 해당 체력 구간의 소환을 소비하지 않고 나중에 다시 시도한다.
- 기본 위치는 보스 기준 X -6, +6이다. 지면과 공간이 없는 위치에는 소환하지 않는다.
- 소환된 슬라임은 기존 슬라임의 접촉 공격/체력/보상을 그대로 사용한다. **보스 접촉 피해 없음 규칙은 보스 본체에 적용**된다.
- 기본적으로 보스 사망/비활성화/StopEncounter 시 자신이 소환한 몬스터를 제거한다. 다른 스포너의 적은 건드리지 않는다.
- 아직 발동하지 않은 경고는 취소한다. 이미 타격이 시작된 영역과 생성된 타격 효과는 정해진 수명을 마친다.

`Golem Boss Controller > Summons`에서 다음을 바꿀 수 있다.

| 설정 | 용도 |
| --- | --- |
| Minion Prefabs | 교체 가능한 소환 적 프리팹. 루트에 EnemyHealth 필요. 보스 프리팹 제외 |
| Summon Health Thresholds | 소환할 체력 비율. 목록 순서대로 처리하므로 큰 수부터 배치 |
| Minions Per Wave / Max Living Minions | 한 번의 소환 수 / 동시 생존 수 |
| Summon Offsets | 루트를 기준으로 한 위치. Y는 지면 탐색 시작 높이 기준 |
| Summon Points | 선택 사항. 씬의 Transform을 넣으면 Offsets 대신 사용 |
| Summon Warning Time / After Summon Rest | 소환 전조 / 소환 뒤 휴식 |

## 나중에 이미지 넣는 위치

이미지가 비어 있어도 플레이 중 몸체·팔·코어·체력바·범위·낙석을 코드로 표시한다. 블록 외형은 임시 플레이스홀더다.

| Inspector 위치 | 넣을 이미지 |
| --- | --- |
| Golem Boss Visual > Idle Sprites | 대기 프레임. 한 장도 가능 |
| Golem Boss Visual > Summon Sprites | 소환 준비부터 등장 직전까지의 동작 |
| Golem Boss Visual > Phase Change Sprites | 페이즈 전환 동작 |
| Golem Boss Controller > 각 공격 > Motion > Prepare | 해당 패턴의 전조 동작 |
| 같은 Motion > Strike | 타격 순간부터 공격 유지 동작 |
| 같은 Motion > Recovery | 팔을 뽑거나 자세를 회복하는 동작 |
| Enemy Animation > Death Sprites | 기존 적과 같은 사망 프레임. Death Frame Time / End Hold Time도 여기서 설정 |
| Golem Boss Controller > Rock Sprite | 떨어지는 돌. 비어 있으면 회색 사각형 |
| 각 공격 > Impact Prefab | 선택 사항. 균열·먼지 등의 타격 이펙트. 최대 5초 뒤 정리 |
| Warning Art > Indicator Fill / Border | 선택 사항. 사각형 면/테두리용 Sprite. 기본 빨간 표시를 그대로 써도 됨 |

- Sprite 배열에 재생 순서대로 넣는다. Animator Controller나 Animation Event는 필요 없다.
- 아트는 투명 배경의 Sprite (2D and UI)로 준비한다. 같은 애니메이션의 프레임은 캔버스 크기와 피벗을 통일한다.
- 보스 프레임은 **Center 피벗**, 기본 몸체 높이 **3.6 월드 유닛**을 기준으로 PPU를 맞춘다. 이미지 교체 때문에 루트 Scale이나 Collider를 함께 키우지 않는다.
- `Sprites Face Right`는 원본 이미지의 방향에 맞춘다. 루트 SpriteRenderer의 Sprite만 바꾸면 플레이 중 덮어쓰이므로 **위 표의 배열에 넣는다.**
- 프레임 수가 늘어도 타격 시점은 Controller의 Warning/Active/Recovery Time으로 유지된다. 경고 중 바닥을 이미 치는 프레임을 넣지 않는다.
- 인디케이터의 커스텀 Sprite는 **Center 피벗의 꽉 찬 사각형**을 사용한다. 원형이나 비대칭 이미지는 사각형 판정과 어긋난다.
- 그림만 바꾸면 동작하지만, 최종 골렘 크기가 달라진다면 몸체 CapsuleCollider와 HP Bar Offset을 아트에 맞춰 한 번 조절한다. 공격 영역 크기는 별도로 유지된다.

## 주요 밸런스와 씬 연결

- 체력/보상: `Enemy Health > Max Hp / Energy Reward`.
- 기본 공격력: `Enemy Stats > Offense`. 각 패턴의 `Damage > Damage Multiplier`가 여기에 곱해진다.
- 패턴: Controller의 각 공격에서 Warning Time, Size, Active Time, Recovery Time, Cooldown.
- 전투 범위: Encounter의 `Arena X`. 보스 최초 X 기준 상대값이며 낙석/소환 위치를 제한한다. 실제 전투 바닥 폭에 맞춘다.
- 자동 시작을 끄고 보스방 트리거에서 `BeginEncounter()`를 호출할 수 있다. `StopEncounter()`는 다음 BeginEncounter 또는 재활성화까지 행동을 중지한다.
- Inspector의 `On Encounter Started / Ended / Phase Two` 이벤트로 문·연출 등을 연결할 수 있다. Ended는 수동 중단에도 호출되므로 클리어 보상을 무조건 여기에 연결하지 않는다.

## 검증 범위

프로젝트의 실제 런타임 소스와 기존 슬라임/피해 처리 코드를 별도 Unity 6000.4.0f1 프로젝트로 복사하여 **39개 Play Mode 회귀 검증을 통과**하고 화면 렌더를 확인했다. 경고 중 무피해, 범위 고정, 범위 밖 회피, 다중 콜라이더 중복 방지, 기존 무적, 낙석 3회 타이밍, 소환 임계값/생존 수 제한, 페이즈 연결/쿨타임, 이미지 교체, 사망/재활성화 정리를 포함한다. 기록은 로컬 `Temp/GolemBossValidation/result.txt`와 `final-playmode.log`, 예고 화면 PNG에 있다. 테스트 프로젝트 시작 시 발생한 UnityEditor.Search 검색 인덱싱 예외는 보스 런타임 검증과 별개로 로그에 남아 있다.

기존 플레이어 프리팹으로 실제 스테이지를 직접 조작한 검증은 별개다. 배치 후 다음을 확인한다.

1. 점프/대시로 빨간 범위를 벗어났을 때 피해가 없는지, 몸을 통과해도 접촉 피해가 없는지.
2. 보스와 경고가 실제 맵의 Sorting Layer, 조명, 카메라 안에서 잘 보이는지.
3. 낙석 표시와 소환 지점이 벽/절벽/낮은 천장과 겹치지 않는지.
4. 기존 플레이어의 공격력에 맞춰 체력 300과 소환 타이밍이 적절한지.
5. 최종 이미지 교체 후 전조·타격·회복 자세와 실제 판정 시점이 맞는지.
